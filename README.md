# ちょっと暇つぶし。

1〜3分で遊べる、くだらないミニゲーム集。
HTML / CSS / JavaScript だけで動作します（ログイン・データベース・外部APIなし）。

| ゲーム | 内容 |
| --- | --- |
| 🗼 東京の街診断 | 10の質問に答えると、ぴったりの東京の街がわかる |
| ⚖️ どうでもいい裁判所 | 日常のどうでもいい事件を入力すると、架空の裁判所が判決を出す |
| 🚃 終電を逃すな | 電車のドアが乗車位置に来た瞬間に「乗る！」を押すタイミングゲーム |
| 🏃 東京を走れ | 夜の東京を自動で走り、タップでジャンプして障害物を避ける横スクロールアクション |
| 🍜 ラーメンを伸ばすな | 麺がどんどん伸びていく。伸び切る前に、タップでひたすら食べる |
| 🏙️ 東京、歩く。 | 小さな3Dの東京を、スマホのジョイスティックや WASD で歩く（Three.js） |

## 使い方

`index.html` をブラウザで開くとゲーム一覧が表示されます。

スマホ実機で確認したい場合は、同じネットワーク内で簡易サーバーを立てるのが便利です。

```sh
python3 -m http.server 8000
# スマホから http://<PCのIPアドレス>:8000 を開く
```

## 新しいゲームを追加するには

1. `games/<ゲームID>/` フォルダを作り、`index.html` などを置く
   - 共通スタイルは `../../assets/common.css`、シェアは `../../assets/share.js` を読み込むと使えます
   - 画面上部に `<nav class="site-nav"><a href="../../">← ちょっと暇つぶし。</a></nav>` を置くと一覧へ戻れます
2. `assets/games.js` の `GAMES` 配列に1件追加する（タイトル・説明・絵文字・色・リンク先）

これだけでトップページにカードが表示されます。

## どうでもいい裁判所

入力された文章に含まれるキーワードから、ルールベースで判決を作ります（外部AIは使っていません）。
同じ文章からは、いつも同じ判決が出ます（文章から乱数の種を作っているため）。

### 判決のしくみ

1. **何をしたか**（`ACTS`）：既読・返信 / 遅刻・待ち合わせ / プリン・食べた / 約束 / お金 / 「なんでもいい」/ スマホ / 家事 / 睡眠
   - 当たったキーワードが最も多いものが罪名になります（同数なら文章の前のほうに出てきたもの）
   - どれにも当たらなければ「どうでもいい罪」などの汎用の判決
2. **誰との事件か**（`PEOPLE`）：家族 / 恋人 / 友達 → 判決理由と裁判長の一言に反映
3. **補正**（`MODIFIERS`）：謝った（−15）、わざと（＋20）、うっかり（−10）、また・いつも（＋15）、初めて（−10）
4. **数字への反応**：「5分」→ 誤差扱い、「3時間」→ カップ麺◯個分、「500円」→ 自販機◯本分、「1万円以上」→ 重め
5. **被告**：「〜された」「返信がない」なら相手、それ以外や「俺が悪い？」ならあなた

有罪度（0〜100%）で判決の種類が決まります。

| 有罪度 | 判決 |
| --- | --- |
| 0〜14% | 無罪 |
| 15〜34% | 情状酌量 |
| 35〜54% | 執行猶予 |
| 55〜84% | 有罪 |
| 85〜100% | 有罪（重め） |

キーワードや文言を増やすときは `games/court/rules.js` を編集し、`node scripts/check-court.js` で確認してください。

## 終電を逃すな

夜の駅で、右から走ってくる電車の**光るドア**が、ホームの **▲乗車位置** に来た瞬間に「乗る！」を押すタイミングゲームです。
画像は使わず、駅・電車・演出はすべて HTML / CSS で描いています。
見た目は小さなゲーム筐体風（電飾の看板・ベゼル付きモニター・LEDの案内表示・アーケードボタン）で、
トップページのゆるい雰囲気との対比を狙っています。タイトルと結果はモニターの中に表示されます。

### 1プレイの流れ

1. 「ゲームスタート」→ 3・2・1 のカウントダウン
2. 制限時間10秒。電車は 1.0〜3.8 秒後のランダムなタイミングで入ってくる
3. 電車は乗車位置の手前で減速し、過ぎると加速する（毎回、速さと減速の強さが少し変わる）
4. 「乗る！」を押した瞬間の、ドアと乗車位置のズレ（ステージ幅に対する割合）で判定
5. 結果画面 →「もう一回遊ぶ」

### 判定

| ズレ | 判定 | 点数 | 表示 |
| --- | --- | --- | --- |
| 3% 以内 | PERFECT | 100点 | 間に合った！ |
| 7% 以内 | GOOD | 70点 | 間に合った！ |
| 12% 以内 | ギリギリ | 40点 | 間に合った！ |
| それ以上（手前） | MISS | 0点 | まだ来てません |
| それ以上（過ぎた）・押さなかった | MISS | 0点 | 終電、行っちゃいました… |

電車が来る前に押した場合も「まだ来てません」で MISS です。
判定の幅や電車の速さは `games/train/app.js` 冒頭の設定値で調整できます。

### シェア

- 「𝕏 結果をシェア」：X の投稿画面を開きます（シェア文・ハッシュタグ #ちょっと暇つぶし・ゲームURL入り）
- 「ほかのアプリでシェア」：スマホの共有機能（Web Share API）が使える環境でのみ表示されます

## 東京を走れ

夜の東京を主人公が自動で走り続けます。画面のどこかをタップ（PCは Space / Enter / クリック）でジャンプして、
コーン・ゴミ袋・水たまり・看板・放置自転車・鳩・タクシー・工事フェンスを避けます。
背景（夜空・タワー・ビルの窓明かり・ネオン看板・街灯・信号・対向車）と主人公・障害物は、すべて CSS / SVG で描いています。

### ルール

- ジャンプは地面にいるときだけ（空中で連打しても高さも回数も変わらない。二段ジャンプなし）
- スコアは走った距離：1m = 10点（例：123m → 1230点）
- 走る速さは時間とともに上がり（30秒で最初の約2倍）、8・15・22・30秒で「SPEED UP!」
- 障害物は時間で解禁：最初は コーン・ゴミ袋 → 5秒 水たまり → 8秒 看板・自転車 → 10秒 鳩・2連続 → 14秒 タクシー → 15秒 工事フェンス → 22秒 3連続

### 理不尽な配置を作らないしくみ（`engine.js`）

- まとまりとまとまりの間隔は「前の障害物をいちばん遅いタイミングで跳んでも、着地してから次に反応できる時間」以上を必ず空ける
- 2〜3個の連続配置は、1回のジャンプで越えられる幅の 7 割以内のときだけ出す
- `node scripts/check-tokyo-run.js` で、先読みする自動プレイが 40 通りの乱数すべてで 60 秒走り切れることを確認できる

## ラーメンを伸ばすな

麺の「伸び具合」が時間とともに 0% → 100% へ増えていき、100% で「🍜 のびました。」。
「🍜 食べる！」ボタン（またはラーメンの画面）をタップ、PC は Space / Enter / クリックで1口食べると伸び具合が下がります。

### ルール

- 1% 食べると 10 点。1杯分（100%）食べるごとに「替え玉！」で +300 点＆伸び具合 −15%
- 伸びる速さは時間とともに上がり、少しだけ波がある
- 1口ごとに口の中がたまり、時間で飲み込む（ボタンの中のゲージ）。口がいっぱいに近いほど1口が小さくなり、
  満杯になると「ゲホッ！」とむせて 1.5 秒食べられず、麺が戻って伸び具合 +12%
- → 連打より「ズズッ…ズズッ…」と1秒に2口くらいのリズムで食べるのがいちばん強い

| 遊び方 | 目安 |
| --- | --- |
| 何もしない | 約10秒で終了 |
| 連打（5〜12回/秒） | 約14〜15秒・2000点前後（むせまくる） |
| リズムよく（2回/秒） | 約21秒・3400点前後 |

数値は `games/ramen/engine.js` の `C` で調整でき、`node scripts/check-ramen.js` でバランスを確認できます。

## ぽよぽよブラスト（V2）

「1つ動かして連鎖を仕込む → タップで消す → 落ちて自動でそろう → さらに連鎖…」で COMBO をつなげる、ステージクリア型のパズルです。キャラクター・絵・音はすべてコードで作ったオリジナルです。

- 1ターンの流れ（`engine.js`）
  - （しなくてもよい）ぽよかブースターを1つ、ドラッグで2マスまで動かせる。手数は減らない。来た道を戻れば取り消し（「もどす」ボタン・Backspace でも）。1ターンに動かせるのは1つだけ
  - 2つ以上つながった同じ色か、ブースターをタップ → 消える（手数 −1）＝ 1 COMBO
  - 落ちて補充されたあと、「動いたぽよ」をふくむ同じ色の4つ以上のかたまりは自動で消える ＝ +1 COMBO。消えるものがなくなるまでくり返す
  - 補充されるぽよの色は、それだけで4つそろわないように選ぶ。連鎖は盤面にあったぽよが落ちたときだけ起きる＝盤面を見れば読める（運まかせの連鎖にしない）
  - 爆風に巻き込まれたブースターの発動・ブースターの合体（となり合ったブースターをタップ）でも COMBO が増える
  - 点数は COMBO の倍率つき（×1 → ×1.5 → ×2 … 最大 ×5）
- ブースター
  - タップで消した数：4つ → ぷちボム（まわり1マス）、5つ → ロケット（1列）、6つ → ボム（まわり2マス）、7つ以上 → レインボー（その色ぜんぶ）
  - 連鎖で消えたかたまりもブースターになる（1つの波でいちばん大きいかたまり1つだけ）。3 COMBO 目からは数が +1、5 COMBO 目からは +2 として数え、さらに「チャージ」つき（ロケット3列・ボム／ぷちボムの範囲が広い・レインボー2色）
  - 合体：ロケット＋ロケット＝十字、ロケット＋ボム＝3列×3列、ボム＋ボム＝大爆発、ロケット＋ぷちボム＝3列ロケット、ボム＋ぷちボム・ぷちボム同士＝広い爆発、レインボー＋ほか＝その色が全部そのブースターに、レインボー同士＝ぜんぶ
- 目標：色のぽよ・木箱・石・ふうせん・プレゼントに加えて、「○コンボ以上を△回」「○○（ブースター）を使う」「ブースター合体」
- 演出：2 COMBO「NICE!」→ 3「GREAT!」→ 4「SUPER!」→ 5「AMAZING!」→ 6「MIRACLE!」→ 7以上「FEVER!」。
  COMBO が上がるほど、数字の大きさ・粒・画面の揺れ（最大 9px）・音の高さ・画面のふちの光が強くなり、連鎖のテンポも速くなる（7 COMBO で約半分の待ち時間）。
  連鎖の直前はそろったかたまりが光ってふくらみ、連鎖がとまった瞬間は少しだけゆっくりになって合計点を表示。
  COMBO の目標にあと1つ届かなかったときは「あと1コンボ！」。手数切れの画面でも、最高 COMBO と次のヒントを出す
- 見やすさ：大きな表示は盤面の上のすき間に出す（すき間が狭い画面では盤面の上のほうに少し透かして）。盤面にさわると薄くなる。光るのは画面のふちだけ
- ステージ（`levels.js`）：全12ステージ。1：タップ、2：ドラッグ（指のお手本）、3：連鎖（指のお手本）、
  4〜12：木箱・ロケット・ひし形・プレゼント・石とボム・合体・ふうせん・5 COMBO・ハート、と COMBO の目標が少しずつ大きくなる
- 操作：スマホは指で（押すとすぐ反応、動かせばドラッグ、その場で離せばタップ）、PC はマウスで同じ。
  キーボード：矢印で選ぶ・Enter / Space で消す・Shift＋矢印で動かす・Backspace でもどす・Esc で一時停止
- 進行（解放したステージ・各ステージの星と最高点・最高 COMBO・音）は端末の localStorage（キー `popoBlastSave.v2`）
- `node scripts/check-blast.js` で、ルールのテスト（タップ・連鎖・COMBO・ドラッグ・ブースター・チャージ・合体・目標・補充）と、
  2種類のボット（タップだけ／ドラッグと先読みあり）で全ステージを遊んで、クリア率・COMBO の出かた・星の割合を確認。`--stars` で星の点数の目安
- `games/blast/v1/` は、V2 にする前のファイルそのままのバックアップ（V1 の進行は `popoBlastSave.v1` に残る）

## 東京、歩く。（5.0）

Three.js で作った小さな東京風の街で、「今日の目的」を3分以内に探す探索ゲームです。

- 探索のルール（`mission.js`）
  - 「探索スタート」→「🎯 今日の目的」（初回だけ操作の説明3行）→ タップ／キーでスタート。制限時間は3分
  - 目的は9種類：赤い自販機・黄色い立て看板・赤い郵便ポスト・黒ねこ・お店（店名）・袖看板・ラーメン屋さん・銭湯・小さな公園
  - 種類を同じ確率で選び、その種類の候補地点（全43か所）から1つを選ぶ。前回と同じ目的は続けて出ない
  - 赤い自販機・黄色い看板・ポスト・ねこは、選ばれた場所に1つだけ置く（ふだんの街には、まぎらわしい赤い自販機やポストを置いていない）
  - 目的物から約2.5〜3.5m（公園は中）に入ると発見。近く（約8m）に来たときだけ小さなきらめきが出る（遠くからは分からない）
  - 点数：発見 100 ＋ 残り時間のボーナス（120秒以上 +100／60〜119秒 +50／30〜59秒 +25／30秒未満 なし）。時間切れは 0
  - ヒント：60秒で「少し遠くまで」、120秒で目的の種類ごとのヒント（場所そのものは教えない）。画面上には方位（N/E/S/W）だけ
  - 最高点は端末の localStorage（キー `tokyoWalkHighScore`）。初回の説明を見たかは `tokyoWalkTutorialSeen`
  - 効果音は Web Audio で、最初のタップのあとだけ鳴らす（使えない環境では無音で続ける）
  - `scripts/check-tokyo-walk.js` で、全候補に歩いて行けること、100回のランダム選択を道順どおりのボットで歩き・走りの両方で見つけられることを確認

  - 約0.4秒かけて 5.8m/秒まで加速。止まるときもすぐ止まる（滑らない）

- カメラは斜め後ろからの3人称。走ると少し後ろへ引いて視野を少し広げる。ジャンプは少し遅れて追い、着地で少しだけ沈む。
  建物・ひさしで視線がさえぎられるときは手前に寄る（寄るときは速く、戻るときはゆっくり）。
  大きく寄ったときは少し上から、少し先を見る。街路樹の葉はカメラより高いので、歩道でカメラが葉に埋もれない

  - スマホ：左下のジョイスティック（触れた場所が中心）で移動、右下の JUMP、右側をなぞってカメラを回す
  - スマホ：DASH ボタンで走る
  - PC：WASD / 矢印キーで移動、Shift で走る、Space でジャンプ、Q / E でカメラを回す
- 軽量化
  - 動かない物は材質ごとに1つのメッシュへ結合（頂点カラー）。40m区画に分けて画面外を描かない
  - 見えない面（底面・建物どうしが接する面・遠景の外側を向いた面）は作らない
  - 影は止まっている物だけを、プレイヤーが6m動いたときにだけ描き直す。プレイヤーの影は足もとの丸い影
  - ひさしは1回の描画（InstancedMesh）。真下に入ったものだけ半透明の別メッシュに差し替える
  - テクスチャ：外壁 1024×512、看板 1024×768。影の地図はスマホ 896px / PC 1536px
  - スマホはアンチエイリアスなし・異方性フィルタ2・ピクセル比を fps に合わせて 1〜1.75 で調整
    （一度重かった解像度には戻さない。下げきっても重いときは影のふちのぼかしをやめる）
  - 外部の3Dモデルや画像素材は使っていません（すべてコードと Canvas で生成）

## 東京の街診断

### 診断のしくみ

- 各選択肢に「街: 加点」が設定されていて、回答ごとに点数を合計します。
- 合計点が最も高い街が結果になり、2位の街が「相性のいい街」として表示されます。
- 同点の場合は、より多くの質問で加点された街を優先します。

### 質問の設計方針

最優先は **「4つのうち最低1つは、自分ならこれを選ぶと思えること」**。
性格を直接聞くのではなく、**生活の具体的な場面で、どう行動するか**を選んでもらいます。

- 4択は「4種類の人間」ではなく「4種類の自然な行動」にする
- 各質問に、家で過ごす・人に合わせるなど**誰でも選べる日常的な行動**を必ず入れる
- 一人・家族・恋人・友人・仕事など、いろいろな生活スタイルの人が選べるようにする
- 街の名物・有名スポット・イメージは選択肢に出さず、結果を予想しにくくする
- 「その他」「どれでもない」は使わない。クスッとする要素は「ちょっと分かる（笑）」程度まで
- 各選択肢は「メインの街に2点 ＋ 近い価値観の街に1点」
- どの街もメイン（2点）5回・サブ（1点）5回、合計15点ずつに統一

### カスタマイズ

質問や街を変えたいときは `games/tokyo-town/data.js` だけを編集すればOKです。

- 街を追加：`TOWNS` に新しいキーで項目を追加し、質問の `scores` からそのキーに点数を入れる
- 質問を追加・変更：`QUESTIONS` の配列を編集する（問題数は自動で反映されます）
